# HOW.md — методика: як з фронтенду MyStat отримати повний опис API

> Документ написаний так, щоб **інша нейромережа (або людина)**, прочитавши його, могла відтворити весь
> аналіз на новій версії mystat.itstep.org і оновити `MYSTAT_API.md`. Читай послідовно — порядок важливий.

## 0. Контекст задачі
- **Мета проєкту:** власна реалізація бекенду MyStat. Артефакт — `MYSTAT_API.md` (повний опис REST + socket.io + файлового сервісу).
- **Вихідники:** статичні JS-бандли Angular (збірник esbuild, рядки в бектиках) + живий API.
- **Ключовий факт:** ліниві чанки — просто статика на `https://mystat.itstep.org/`, їхні імена лежать рядками всередині інших чанків. Браузер/DevTools НЕ потрібні.

## 1. Стартовий набір
Достатньо `https://mystat.itstep.org/` (index.html). З нього беремо `main-<hash>.js` і `polyfills-<hash>.js`
(до жовтня 2026 це був `main.js` з фіксованою назвою); решта дочитується за алгоритмом §2.
Версію збірки можна звірити: `GET https://mystat.itstep.org/assets/version.json` → `{"version":"1.0.3"}`.

> ⚠️ `version.json` НЕ змінюється при кожній перезбірці (у жовтні 2026 збірка змінилась, а версія лишилась `1.0.3`).
> Надійний маркер — поле `release` (git-sha) у environment-чанку (§3.1).
> Автоматизація: `python -I tools/fetch_bundles.py <нова_тека>` та `python -I tools/diff_bundles.py <стара> <нова>`.

## 2. Збір УСІХ чанків (ітеративно)
```text
1. по всіх локальних *.js пройтись regex:  chunk-[A-Za-z0-9_-]{4,14}\.js   → множина refs
2. missing = refs − імена файлів на диску
3. кожен missing скачати:  GET https://mystat.itstep.org/<name>
   заголовок User-Agent справжнього браузера ОБОВ'ЯЗКОВИЙ (інакше CDN ріже)
4. повторювати кроки 1–3, поки missing != ∅ (скачані чанки посилаються на нові). Зазвичай хапає 3–4 проходів
```
Робочий варіант — PowerShell-скрипт із циклом до 4 проходів (див. історію: 69→18→1→0).

## 3. Що і як шукати в бандлах
### 3.1 Середовище
Найменший чанк (<1 КБ, виду `chunk-XXXXXXX.js`, без коду) містить прод-конфіг:
`apiUrl` (https://mapi.itstep.org/v1), `apiModule` ("mystat"), `notifySocketUrl`/`logSocketUrl`/`chatSocketUrl`,
`cryptoKey`, `appId`, `isMultiBranches`. Це база всіх адрес.

### 3.2 HTTP-шар
- **Виклики:** regex `\.(get|post|put|delete|patch)(?:<[^(]{1,120}>)?\(\s*[`"]([^`"]{1,110})[`"]`
  (дістає і шаблони `${id}`; обрізати контекст ±130 символів навколо збігу).
- **Generic base-service:** клас із методом `getEndpoint()` — додає префікс `/{branch_alias}`, якщо `isMultiBranches`.
  Підкласи задають поле `endpoint='/students'` тощо. Тому прямих httpClient-викликів мало — шукай присвоєння `endpoint=`.
- **Літерали шляхів:** усі бектик-рядки, що починаються з `/` (виключити `/assets`, розширення css/js/png/svg).
- **Інтерцептори:** заголовки `Authorization: Bearer`, `X-Language`, `X-UserId`; логіка refresh при 401;
  глобальний лоадер і його винятки.
- **Пагінація:** три стилі (laravel: `pagination[page]`, yii: `page/per_page`, flask: `limit/offset`);
  номери сторінок приходять заголовками відповіді `X-Pagination-Current-Page` / `X-Pagination-Page-count`.

### 3.3 Сокети (socket.io)
URL із середовища (§3.1). Опції підключення: `{query:{alias}, auth:{token}, extraHeaders:{'ngrok-skip-browser-warning':'69420'}}`.
Події: regex `\.(on|emit)\([`"]([A-Za-z_][\w.\-]{1,50})[`"]`.

### 3.4 Інше
localStorage-ключі (`access_token`, `admin_token`, `child_id`, `branch_alias`, `file_token`, …),
authConfig (`endpointLogin`, `endpointRefresh`, …), стилі помилок (масив `{field,message}`).

## 4. Граблі PowerShell (усі були набиті!)
1. **Не пиши inline-команди** зі вкладеними лапками через `powershell -Command "..."` — екранування ламається.
   Завжди створюй `.ps1` файл інструментом запису файлів і запускай `-File script.ps1`.
2. **Оператор `-f` падає**, якщо в аргументі є `{}` (а шаблони URL — це `/${id}/...`). Використовуй конкатенацію `"[" + $verb + "] " + $u`.
3. `Measure-Object` може бути недоступний з cmd-контексту — рахуй через `$array.Count`.
4. Великі вибірки — пиши в txt-дайджест і читай частинами, не в stdout.
5. Backtick у PS — escape-символ: у regex обертай усе в **одинарні** лапки.

## 5. Жива перевірка (опціонально, тільки читання)
1. Потрібен access-токен реального акаунта (користувач дістає з DevTools → Network → заголовок `Authorization`).
   **Ніколи не зберігай токен у файли** — тільки env/змінна сесії. Токен помирає після logout користувача.
2. Розшифруй payload JWT (2-га частина, base64url): отримаєш `branch_alias`, `lang`, `exp`, `sub`(logbook_id), `id_user_storage`.
3. Заголовки запитів: `Authorization: Bearer <jwt>` + `X-Language: <lang>`. Тільки GET і безпечні POST (`/auth/me`).
4. Кожну відповідь зберігай: `examples/<ім'я>.json` (`ConvertTo-Json -Depth 12`).
5. **404 — це нормальний результат**: значить фіча вимкнена у філії (для гілки `pl`: counters-header,
   achievements, social-review, contract/conditions). Позначай ❌, а не видаляй.
6. Особливі випадки поточної версії:
   - `/v1/mystat/translate` видалено з прода → переклади статикою `assets/i18n/{lang}.json`;
   - хост файлового сервера динамічний: `GET /{alias}/user/file-token` → зараз `fsx3`, аватарки на `fsx1`, статика на `fs1`;
   - ~~розклад в іншому модулі~~ ВИПРАВЛЕНО 2026-08 живим клієнтом: шляхи ГІЛКОВІ
     `${apiUrl}/mystat/{alias}/schedule/*`; клас з абсолютним endpoint `logbook/kiev`
     у чанку існує, але його URL дають 404 — не плутай «клас є» і «шлях робочий».
   - **Механіка getEndpoint (чанк `CzwpjCl-`)**: `getEndpoint(i,e)` =
     `(multiBranch ? '/'+alias : '') + (i || this.endpoint)`.
     Виклик **без аргумента** підставляє `this.endpoint` класа — це НЕ корінь!
     Приклад: endpoint='/mailing' + `getEndpoint()+'/send-confirmation'`
     = `/v1/mystat/{alias}/mailing/send-confirmation`. Читай сигнатуру, а не вгадуй.
   - **Статуси — енами, не рядки**: домашка `{Done:1, Examination:2, UntilExecution:3,
     Retake:5}` (значення 4 немає); замовлення магазину 1|3=нове, 2|5=скасоване, 4=закрите;
     якість відгуків — рядки `excellent/good/bad`. Шукай у бандлах
     `status===`, `c[c.X=N]=`, таби роутера (`data:{status:N}`).
   - **Евристика 404 vs 401** (живий сервер): 401 = маршрут є, токен поганий;
     404 ДО авторизації = маршрута нема взагалі. Так довели `{id}` у
     `/survey-user-attempts/{id}` і вимкненість `/missions/get-list` на pl.
   - **Порядок маршрутів FastAPI**: статичні шляхи оголошуй РАНІШЕ динамічних
     `{param}` або став конвертер `{param:int}` — інакше 422 замість потрібного роута
     (ловили двічі: files.py і homework.py).
   - **Перевірка токена — тільки скриптом, ніколи інлайном**: JWT декодувати/перевіряти
     пітоном (`tools/probe_verify.py` читає `token.txt`). Інлайн у PowerShell ламається
     об екранування cmd — запит іде без `Authorization` → хибний 401; а `$env:VAR`
     не живе між окремими викликами шелла — скриптові йде порожнеча/старе значення →
     теж хибний 401. Хибний висновок «токен мертвий» коштував кола дебагу 2026-08-24,
     хоча токен був живий (41/50 → 200).
   - **401 — не завжди мертвий токен**: спочатку відтвори запит пітоном з токеном з
     token.txt — «bearer only» вже дає 200, для API обов'язковий тільки `Authorization`
     (`X-L-Session`/`Origin`/`Referer`/UA браузера необов'язкові). 400/500 на кривих
     параметрах теж доводять існування маршрута (розширена 404-евристика).
   - **Форми відповідей підглядай наживо**: `homework/list?status=5` повертає МАСИВ
     секцій `[{status, data, _meta}]`, а не об'єкт; вкладений `homework_stud.status` —
     окремий енам (наживо видені 1 і 6); `statistic/attendance|progress` без `period`
     → 400; `contacts/get-reference-status` повертає голий `true`.

## 6. Конвенції `MYSTAT_API.md`
- Маркери: **✅** підтверджено кодом бандлів · **⚠️** відновлено непрямо · **🟢** підтверджено живим запитом · **❌** 404 на філії.
- Структура: §1 адреси → §2 auth/заголовки/JWT → §3 auth-ендпоінти → §4 похідні акаунта → §5 конфіг філії
  → §6 навчальні сервіси → §7 адмін → §8 файловий сервіс → §9 сокети → §10 інше → §11 карта UI↔API
  → §12 curl-приклади → §13 зведена таблиця (+підсумок живої перевірки) → §14 розділи з лінивих чанків.
- Сирі відповіді живої перевірки зберігати в `examples/` — вони ж фікстури для тестів свого бекенду.

## 7. Процедура при ВИХОДІ НОВОЇ ВЕРСІЇ сайту
1. `GET /assets/version.json` і `release` з environment-чанка — порівняти зі старими; якщо збігаються обидва — нічого не робити (самої версії недостатньо, див. §1).
2. Скачати index.html + `main-*.js` в НОВУ окрему папку (`tools/fetch_bundles.py`), зібрати чанки (§2).
3. Прогнати екстрактори (§3) — або одразу `tools/diff_bundles.py`: він порівнює рядкові літерали двох збірок (хеші чанків і імена змінних щоразу інші).
4. **Diff** зі старими списками: нові ендпоінти → додати у відповідні секції; шляхи, що змінилися —
   позначити «було/стало»; зниклі — позначити `[видалено у vX.Y]`, не видаляти (історія корисна).
5. Нові/змінені GET — жива перевірка (§5), оновити маркери і зведену таблицю §13, зміст.
6. Якщо структура секцій не влазить — заводити §15+, старе не чіпати.

## 8. Шпаргалка: карта модулів API (актуально для v1.0.3)
| Модуль | Префікс | Примітка |
|---|---|---|
| Основний сервіс | `https://mapi.itstep.org/v1/mystat/{alias}/*` | майже все |
| Auth | `…/v1/mystat/auth/*` | без гілки |
| Розклад | `…/v1/mystat/{alias}/schedule/*` | get-month?type=week&date_filter=<ПН> 🟢 |
| Файловий | динамічний хост із `user/file-token` (fsx3) | свій JWT на 48 год |
| App-config | `…/v1/config/1` | публічний |
| Переклади | `mystat.itstep.org/assets/i18n/{lang}.json` | статика, публічно |
| Сокети | notify-/log-/chat-socket-logbook.itstep.org, log-socket-mystat.itstep.org | див. §9 доки |

```

examples/   живі відповіді API (JSON) + i18n словник
tools/      повторно використовувані скрипти (fetch_examples.ps1 і майбутні екстрактори)
```
